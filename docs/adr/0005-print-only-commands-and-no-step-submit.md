# ADR-0005: レンダーコマンドは表示だけにし、間引きは `submit` で拒否する

- ステータス: 採用（2026-10-28）

## 背景

利用者は、QueueWatch を通さず、直接 Blender / husk / hbatch で描きたい場合がある。
また、`1-100x2`（2 フレームおき）のような間引きを使いたい。
QueueWatch のジョブは、連続した `frame_start` / `frame_end` しか持たない。

## 決定

- `commands` は、コマンド行を作って表示するだけにする。実行しない。
- 間引きのあるスライスは、`submit` で拒否し、`commands` を案内する。
- 表示する行は、引用符つきで作る（コピーしてそのまま使える）。hbatch の出力ドライバー名は、コマンドを足せない形（英数字・`_ . - /`）だけを許す。シーン名は、`-` で始まるものと制御文字を拒否する。

## 結果

- 良い点: ツール自身が、任意のコマンドを起動しない。安全性の説明が単純になる。
- 良い点: 利用者が、実行する場所（ローカル、別のファーム）を選べる。
- 悪い点: 実行は利用者の手間になる。
- 悪い点: 実行して確かめたのは Blender だけ。husk と hbatch は、各ツールの `--help` でフラグを確認した段階（README の制限に記載）。

## 検討した代案

- コマンドを実行する（`--run`）: 任意のプログラムの起動になる。検査すべき範囲が大きく広がる。
- 間引きを、1 フレーム 1 ジョブに展開して投入する: ジョブ数が増えすぎる。
