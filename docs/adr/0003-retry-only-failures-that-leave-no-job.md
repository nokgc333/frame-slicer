# ADR-0003: 再送は「ジョブが作られていない」失敗だけにする

- ステータス: 採用（2026-10-28）
- 関連: [ADR-0001](0001-use-urllib-from-the-standard-library.md)

## 背景

ジョブの作成（POST）は、冪等ではない。
QueueWatch は `Idempotency-Key` を解釈しないので、同じ POST を 2 回受けると、ジョブが 2 つできる。
読み取りのタイムアウトでは、サーバーが作成済みかどうか、クライアントには分からない。

## 決定

再送するのは、ジョブが確実に作られていない失敗だけ。

- 接続できない（接続拒否、名前解決の失敗）
- HTTP 429、HTTP 503（受け付ける前の拒否）

読み取りのタイムアウトと、その他のエラーは再送しない。
待ち時間は、上限つきの指数バックオフに、全ジッターを付ける（0.5 秒から始め、上限 8 秒、最大 4 回）。
`Retry-After` があれば従う（上限 30 秒）。
再送のたびに、同じ `Idempotency-Key` を送る（サーバーが対応したときのために）。

## 結果

- 良い点: 再送で、ジョブが二重にならない。
- 良い点: 一時的な過負荷や起動待ちは、自動で越えられる。
- 悪い点: 遅い応答で失敗したときは、人が状態を確かめる必要がある。マニフェストと `status` で確かめられる。
- 悪い点: サーバーが `Idempotency-Key` に対応するまで、キーは保証にならない（README の制限に記載）。

## 検討した代案

- すべての失敗を再送する: タイムアウトのあとに二重投入が起きる。
- 再送しない: 一時的な過負荷で、投入が途中で止まる。
- GET（読み取り）は同じ方針にした: 副作用がないので、条件を分ける利点が小さい。
