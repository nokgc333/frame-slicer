# ADR-0004: 失敗したジョブは、新規ではなく `requeue` で戻す

- ステータス: 採用（2026-10-28）
- 関連: [ADR-0003](0003-retry-only-failures-that-leave-no-job.md)

## 背景

スライスが失敗（`dead`）したとき、同じ範囲のジョブを新しく作ると、キューに同じスライスが 2 つ残る。
どちらが正か、あとから分からなくなる。
QueueWatch には、`dead` と `cancelled` のジョブを同じ id のまま戻す `requeue` がある。

## 決定

- 投入の結果は、マニフェスト（JSON）に残す。スライスごとに id と状態を持つ。
- `retry` は、送れなかったジョブ（id なし）を送り、`dead` / `cancelled` のジョブを `requeue` する。それ以外には触れない。
- すでにあるマニフェストには、`submit` で書かない。続きは `retry`。

## 結果

- 良い点: 同じスライスが二重にならない（実ワーカーで、ジョブ総数が増えないことを確認した）。
- 良い点: 途中で止まっても、マニフェストから続きができる。
- 悪い点: マニフェストの管理が要る。`--manifest` を付けない `submit` は、再実行で二重になる。
- 悪い点: `requeue` は QueueWatch の機能に依存する。

## 検討した代案

- 失敗した範囲を、新しいジョブとして投入し直す: 二重が残る。
- 名前でキューを検索して、重複を避ける: 名前は一意の保証がない。検索が重い。
